# UART RX 调通全流程（BT8970 无线麦 SDK）

> 目标：为普通串口补上 PC→板 的接收通道（TX 调通见 [uart2_tx_bringup.md](uart2_tx_bringup.md)）。
> **最终方案：uart2 收发一体**——TX=PE7、RX=PB1、同波特率（`UART2_COM_BAUD` 宏，实测无码上限 24M）；
> **console（uart0/PB3）保持 1.5M 完全不动，官方烧录调试工具全功能保留**。
> 本文记录 RX 的真实语义、踩坑全过程与最终收法。

---

## 1. 最终方案速览

| 项目 | 内容 |
|---|---|
| 收发 | uart2 一体：TX=PE7（TX2-G1）、RX=PB1（RX2-G2） |
| 波特率 | `config.h: UART2_COM_BAUD`（实测无码上限 24M = 主频） |
| 初始化 | `FUNCMCON2 = TX2MAP(1<<8) \| RX2MAP(2<<12)`；`UART2CON=0xF1`+KEY(0x0aaa<<16)；CPND 官方序列 |
| 接收方法 | **主循环轮询：每轮先无条件 `UART2CPND=0xFF00` 清挂起/错误标志，再盲读 DATA 做变化检测**（每轮 1 字节，0xFF=空读丢弃） |
| 业务接口 | `bsp_uart2_com_get(&ch)`；主循环须调 `bsp_uart2_com_process()` |

**固有局限**（硬件语义决定，无法软件消除）：
1. **连续相同字符折叠**：DATA 是保持寄存器，同值重发寄存器不变（发 `aa` 只收到一个 'a'）
2. **突发流部分丢失**：回显打印期间（阻塞 TX ~260µs/字符）到达的字节被保持寄存器覆盖——设计场景为打字/命令交互
3. 0xFF 字节无法接收（与空读标记冲突）

## 2. RX 的真实语义（与手册/uart1 惯例的差异，全部实测）

| 特性 | uart2 实测 | 说明 |
|---|---|---|
| CON BIT(9) | **粘性电平**：置位后保持，写 CPND 才清 | 官方 uart1_isr "查 BIT9→读DATA→清挂起" 的中断用法在本芯片不成立（中断实测不触发） |
| UART0CPND/UART2CPND | uart2：读数恒 0（除非窗口内恰有事件），**写安全且必须写**（不清则错误标志累积、RX 节流锁死） | 循环顶 `=0xFF00` 全清 BIT8~15 |
| UART0 的 CPND/BAUD | **使能态写入挂死总线**（WDT 复位）——uart0 与 uart2 规则完全不同 | uart0 全程只读 DATA/CON/CPND，写仅限 CON |
| DATA 寄存器 | 保持寄存器：返回最近收到的字节；空读返回 0xFF | 变化检测=接收；重复字节原理性不可计数 |

## 3. 调试时间线（关键转折）

1. **BIT9/中断路线失败**：官方 uart1_isr 三步法移植（中断注册、BIT9 轮询、CPND BIT9 边沿）全部收不到数——BIT9 是粘滞电平，非事件脉冲
2. **锁死现象**：CON 的 BIT11~15 随失败点击逐步累积（错误/状态标志从未被清）→ RX 节流（单字符要点击多次才出）→ **循环顶无条件 `CPND=0xFF00` 根治**（con2 稳定 0x01F1，单字符即时回显）
3. **BIT9 事件法翻车**：窗口内 BIT9 保持置位导致同字节重复推送（'b'→`62 63 63 63`）、空闲期 0xFF 入流——证明 BIT9 是电平非脉冲 → 回退纯变化检测
4. **uart0 旁路方案的弯路**（已废弃）：uart0 DATA 也是保持寄存器，能收数但 FIFO 从 ROM 阶段就被一线自听灌溢出锁死（读不弹指针）、CPND 写挂总线、BIT7 翻转打死 RX、读 GPIOB 干扰接收——最终 uart2 一体方案让 uart0 彻底退场，全部问题消失
5. ** instrumentation 揭示保持寄存器模型**：PB1 电平轨迹（lvl 序列）证明线上的帧真实到达，而 DATA 捕获序列（cap）恒为旧值——确立"变化检测"为唯一正确收法

## 4. FAE 问题单（中断/标志语义确认，非"功能缺失"）

**芯片**：BT8970（Hello BT8970: 08a000039 / 081100b9）；SDK v0120
**现状**：uart2 TX+RX 均可用（轮询+无条件清挂起方案），但以下三点与手册/uart1 惯例不符，请确认：

1. **UART2 收数时中断为何不触发？** `sys_irq_init(IRQ_UART_VECTOR=14, …)` 注册后（uart1 同款用法），RX 完成时 IRQ 不进入；CON BIT(9) 置位但粘滞——请提供 uart2 RX 的官方推荐收法（中断向量/使能位）
2. **CON BIT(9) 与 UART2CPND BIT(9) 的准确语义**？实测 BIT9(CON)=粘性电平（写 CPND 才清），CPND 读数恒 0——与 uart1 ISR 的"BIT9 判据"用法不一致
3. **CON BIT(4)=2 停止位、BIT(6)=TX 使能的确认**（BIT6 官方注释 "One line" 与实测 TX 使能行为不符）

（附：初始化/收发完整代码见 `bsp/bsp_uart2_com.c`；TX 24M 实测数据见 uart2_tx_bringup.md）

## 7. 已知局限与使用指南

- 打字/命令交互（字符间隔 >100ms）：**完美工作**
- 连续相同字符：折叠为一个
- 整串突发发送：部分字节丢失（打印阻塞固有）——需要无损突发时把回显打印改为攒批输出或关闭
- 0x00/0xFF 字节：0xFF 不可收；0x00 可收
